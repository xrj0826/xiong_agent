# 餐饮员工管理系统 V1.0 — 排班管理 PRD

| 项目 | 内容 |
|---|---|
| 文档编号 | SCHED-01 |
| 版本 | V1.0 |
| 状态 | 排班状态、周视图已确认；每周应休限制待确认 |
| 操作人 | 已登录的总部账号 |
| 前置依赖 | 门店管理、员工管理 |
| 下游依赖 | 考勤管理；后续月度考勤核对及工资核算 |

## 1. 模块目标

总部按门店、自然周给员工安排下周工作/早班/休息/请假，并支持手动调整、复制上周排班及查询历史记录。页面尽量直接，不需要门店审批、员工登录或通知发布。

## 2. 已确认排班规则

**每天四选一：上 / 上（早） / 休 / 假。**

| 状态 | 含义 | 计入上班天数 | 计入早班次数 | 计入休息天数 | 计入请假天数 |
|---|---|---:|---:|---:|---:|
| 上 | 正常上班 | 1 | 0 | 0 | 0 |
| 上（早） | 上早班 | 1 | 1 | 0 | 0 |
| 休 | 排休 | 0 | 0 | 1 | 0 |
| 假 | 请假 | 0 | 0 | 0 | 1 |

- 员工每天最多且仅选择一个正式排班状态。
- **上（早）不增加额外一个上班天数**，只是“上”的早班类型。
- 「假」是计划/排班标记，不直接代表请假已经审批或工资必须扣减；请假原因及计薪处理由考勤模块定义。
- 不记录具体上下班时间；不建立早/晚/全天等更多班次类型。
- 默认打开**下一自然周（周一至周日）**。

## 3. 功能清单

| 编号 | 功能 | V1.0 范围 |
|---|---|---|
| SCHED-001 | 选择门店 | 顶部门店下拉框，切换排班门店 |
| SCHED-002 | 切换周次 | 默认下一周，可切换历史或未来周次 |
| SCHED-003 | 周排班表 | 行为员工，列为周一到周日 |
| SCHED-004 | 单元格编辑 | 点击某天单元格，在四种状态中选择 |
| SCHED-005 | 统计汇总 | 每人显示上班、早班、休息、请假天数 |
| SCHED-006 | 保存排班 | 保存该门店、该周排班信息 |
| SCHED-007 | 复制上周 | 按员工对应星期复制上一周排班并允许调整 |
| SCHED-008 | 历史查询及修改 | 查看已有排班，并允许更正，保留必要修改记录 |

**不做：**AI 自动排班、班次时刻配置、门店员工线上确认、推送通知、审批流、复杂工时核算、自动判断劳动法休息时长。

## 4. 页面结构

### 4.1 周排班页面

布局建议：

1. 顶部：门店下拉框；周次切换（上周/下周或周选择器）；当前周日期范围。
2. 操作栏：「复制上周」「保存」。
3. 表格左侧第一列为员工姓名；其后为周一、周二、周三、周四、周五、周六、周日。
4. 表格右侧汇总：上班天数、早班次数、休息天数、请假天数。
5. 点击表格单元格时弹出「上 / 上（早） / 休 / 假」选择器；选择后即时显示修改，但正式入库在点击「保存」后完成。
6. 对尚未排班的可编辑日期，可临时显示“未设置”的占位状态；**这不是第五种正式排班选项**。
7. 对员工尚未入职、已离职或不属于此门店的日期显示“—”（不可编辑），也不是第五种排班状态。

文字示意：

| 员工 | 周一 | 周二 | 周三 | 周四 | 周五 | 周六 | 周日 | 上班 | 早班 | 休 | 假 |
|---|---|---|---|---|---|---|---|---:|---:|---:|---:|
| 张三 | 上 | 上（早） | 休 | 上 | 上 | 上 | 休 | 5 | 1 | 2 | 0 |
| 李四 | 休 | 上 | 上 | 上（早） | 假 | 上 | 上 | 5 | 1 | 1 | 1 |

> 示例用于说明展示方式，不代表实际员工或实际排班。

### 4.2 门店和员工呈现

- 门店只能从已建档且营业中的门店中选取，用于新周排班。
- 正常编辑时，根据所选周次逐日校验员工与门店的在职归属关系。
- 员工中途入职、离职或转店时，不应给其不适用日期排班。
- 查询历史排班时，员工即便后来离职或转店，仍应看到当时已保存的排班信息。

### 4.3 复制上周

- 根据上一个自然周同一门店、同一员工 ID、同一星期位置复制状态。
- 上周没有排班时提示“上周暂无排班可复制”。
- 本周已有未保存更改时，复制前要求确认是否覆盖当前编辑内容。
- 只对本周有排班资格的员工和日期复制；新员工未匹配到历史数据的日期保持待设置。
- 复制仅填入当前编辑草稿，点击「保存」才写入正式排班。

## 5. 数据字段

### 5.1 周排班业务主键

| 字段 | 类型 | 说明 |
|---|---|---|
| 门店ID | 关联ID | 选中门店 |
| 周起始日期 | 日期 | 对应自然周周一 |
| 周结束日期 | 日期 | 对应自然周周日（可按周一推导） |
| 排班版本/更新时间 | 版本或时间 | 防止后续覆盖、支持必要的变更追溯 |

### 5.2 每日排班明细

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 员工ID | 关联ID | 是 | 不用姓名作为关联标识 |
| 门店ID | 关联ID | 是 | 记录排班时的归属门店 |
| 排班日期 | 日期 | 是 | 对应具体自然日 |
| 排班状态 | 枚举 | 是 | 上 / 上（早） / 休 / 假 |
| 修改时间 | 日期时间 | 自动 | 审核及查错依据 |

建议使用“门店ID + 员工ID + 排班日期”限定每天仅有一条有效排班记录；员工调店当日的跨店规则需与员工管理模块保持一致。

## 6. 业务规则

1. **周维度：** 自然周为周一到周日；系统默认下一周。
2. **员工每天四选一：** 不允许同一天同时“上”和“休”等冲突状态。
3. **完整性：** 已保存的周排班，对每个具备排班资格的员工日期需要有一个正式状态；空白仅用于未保存编辑草稿（简化建议）。
4. **可调整：** 排班保存后可再次修改，重新保存后更新，保留修改时间及必要修改记录。
5. **统计：** 上班天数=“上”天数+“上（早）”天数；早班次数=“上（早）”天数；休息天数=“休”天数；请假天数=“假”天数。
6. **不做工时计算：** “上（早）”不等于约定具体工时，V1.0 不自动推算工作小时数或加班。
7. **历史可查：** 不因员工后来离职、调店或门店后来停用而丢失原始排班。
8. **考勤独立：** 计划排班可能与实际出勤不同，考勤以考勤管理数据为准；仅有“假”排班状态不能自动认定扣款。
9. **休息天数：** 暂按总部可灵活安排处理，不在保存时强制每人每周固定休息 1 天；此为便于先行设计的建议，最终需确认用工规则。
10. **保存保护：** 如用户改动后切换门店/周次或离开页面，提示未保存更改，防止误丢失。

## 7. 异常场景

| 场景 | 系统预期行为 |
|---|---|
| 该门店尚无员工 | 展示空状态，不生成虚构排班 |
| 选择的周次尚未排班 | 显示可编辑草稿；保存前完成可排日期 |
| 复制上周但无数据 | 友好提示，保留现有草稿 |
| 复制上周遇到新入职/离职/转店人员 | 仅复制匹配且当日有效的日期，其余按规则处理 |
| 在员工入职之前或离职之后排班 | 禁止保存无效日期的记录 |
| 保存时存在未设置的可排日期 | 提示具体员工与日期，阻止不完整保存（建议） |
| 保存时网络失败 | 保留编辑草稿并提示失败，避免认为已保存 |
| 切换门店/周次时有未保存修改 | 弹出“离开将丢失未保存修改”的确认 |
| 历史排班所涉及门店已停用 | 历史仍可查看；不允许给停用门店新增未来排班 |
| 多次点击保存 | 不应产生员工同一天的重复有效排班 |

## 8. 验收标准

- [ ] 排班页默认显示下一自然周，日期从周一到周日。
- [ ] 切换门店后，展示对应门店符合日期归属条件的员工。
- [ ] 任一可编辑单元格仅能选择“上、上（早）、休、假”四种正式状态。
- [ ] 上（早）计入一个上班天数、一个早班次数，不重复累计上班天数。
- [ ] 每位员工的上班、早班、休、假四项统计与排班表一致。
- [ ] 可以保存周排班，刷新后能够还原。
- [ ] 复制上周正确映射同门店、同员工、同星期；并可编辑后保存。
- [ ] 已保存排班可修改，历史周排班能够查询。
- [ ] 员工后来离职或转店，不丢失原门店历史排班。
- [ ] 不允许在员工不归属门店或不在职的日期新建排班。
- [ ] 保存失败、未保存离开等异常有正确提示。

## 9. 待确认

- 每位员工每周的休息天数是否完全自由、是否有最少休息天数要求？本文暂不设置固定限制。
- 排班里的“假”是否细分事假/病假/年假？V1.0 排班界面按已确认方案仍仅一个“假”，请假种类留待考勤管理模块处理。
- 是否需要针对工作日、周末、节假日做不同提示或最低到岗人数提示？V1.0 暂不做。
- 是否允许只保存部分员工的排班？本文建议“一次保存完整的可排日期”，若业务希望随时存草稿可调整。

> 排班的四种状态与周视图已确定；上面列出的待确认项不应被理解为额外增加的功能。
