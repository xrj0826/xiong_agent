# 餐饮员工管理系统 V1.0 — 员工管理 PRD

| 项目 | 内容 |
|---|---|
| 文档编号 | EMP-01 |
| 版本 | V1.0 |
| 状态 | 主要需求与薪资配置方案已确认；计薪边界待薪资模块细化 |
| 操作人 | 已登录的总部账号 |
| 前置依赖 | 门店管理、总部登录 |
| 下游依赖 | 周排班、考勤、绩效与工资核算 |

## 1. 业务目标

在总部后台按门店管理员工档案，支持员工入职、编辑、转店、离职及独立薪资结构配置。每名员工可同时拥有多个不同薪资组成项目；薪资项目库在全系统共享，但员工配置互不影响。

## 2. 已确认产品决策

- 员工列表按门店展示：页面顶部**门店下拉框**，选择后显示该门店员工。
- 员工离职需**二次确认**；离职后从正常员工列表移除；不得物理删除历史记录。
- 岗位固定三种：**普通员工 / 副店长 / 店长**。
- 员工薪资**每个人独立配置**，可选多个项目且项目组合不同。
- **单量提成固定 0.1 元/单**，不是每人自行设置提成系数。
- 单量提成公式：**员工所属门店当月总单量 × 0.1 元/单**；只有配置该项目的员工计算该提成。
- 薪资项目采用**全局共享项目库**；允许自定义新增薪资项目。
- 自定义项目在 V1.0 支持“固定金额”和“月度录入”；复杂自定义公式暂不做。

## 3. 功能清单

| 编号 | 功能 | 范围 |
|---|---|---|
| EMP-001 | 门店筛选及员工列表 | 选门店后只列该店在职员工 |
| EMP-002 | 新增员工 | 录入档案、岗位及归属门店 |
| EMP-003 | 编辑员工 | 修改基础信息，调整薪资配置 |
| EMP-004 | 员工离职 | 二次确认，转为离职，不再出现在默认列表 |
| EMP-005 | 员工调店 | 修改门店归属并留存历史归属 |
| EMP-006 | 查询离职员工 | 单独入口查看已离职人员及历史资料 |
| EMP-007 | 全局薪资项目库 | 预设项目、自定义项目、新增及停用 |
| EMP-008 | 员工薪资配置 | 多项目选择、独立金额、生效日期及历史版本 |

**不做：**员工自助账号、招聘、合同、在线审批、跨店同时兼职、通用公式设计器、自动个税/社保计算。

## 4. 页面与交互

### 4.1 员工列表页

页面结构：
1. 顶部：门店选择下拉框（仅展示可用门店，默认选第一家；无门店时引导先创建门店）。
2. 顶部右侧：「新增员工」按钮。
3. 列表：姓名、手机号、岗位、入职日期、操作。
4. 每行操作：「编辑」「离职」。
5. 另设「查看离职员工」入口，不混入正常在职列表。

关键规则：切换门店刷新列表；无需进入门店详情再找员工。列表中的身份证号不直接明文展示。

### 4.2 新增/编辑员工页面

建议两块区域：

- **基本信息**：姓名、手机号、身份证号、所属门店、岗位、入职日期。
- **薪资配置**：选择多个薪资项目，配置金额/计算来源，填写生效日期。

按钮：「保存」「取消」。保存时同时校验基础信息和已设置薪资项目是否有效。

### 4.3 离职确认交互

1. 总部点击员工行「离职」。
2. 弹出二次确认：显示员工姓名、当前门店、离职生效日期；明确提示“确认后员工将从在职列表移除，历史数据仍保留”。
3. 总部点击「确认离职」后修改状态为“离职”；点击「取消」不做修改。
4. 成功后刷新在职列表，该员工不再显示。

V1.0 可按“确认即办理离职”实施；未来日期的预约离职暂不在本轮范围内。

### 4.4 薪资项目库页面

| 列 | 说明 |
|---|---|
| 项目名称 | 如基本工资、单量提成、岗位津贴 |
| 收支方向 | 增加工资 / 减少工资 |
| 计算类型 | 固定金额 / 每月录入 / 系统自动计算 |
| 项目来源 | 系统预设 / 自定义 |
| 状态 | 启用 / 停用 |
| 操作 | 查看、编辑允许的字段、停用 |

新增项目表单：项目名称（必填）、收支方向（必填）、计算类型（自定义只允许固定金额或每月录入）、备注（选填）。

**系统预设项目建议：**
- 基本工资：固定金额，员工分别填写元/月。
- 单量提成：系统自动计算，规则固定为门店月单量 × 0.1 元/单。
- 店长绩效：系统自动计算，数据来自后续店长绩效评估；具体评估转换公式待绩效模块确认。
- 考勤调整：系统自动计算或从考勤核算结果带入；细则待考勤/薪资模块确认。

**自定义项目示例：**岗位津贴（固定金额）、住房补贴（固定金额）、临时奖金（每月录入）、全勤奖（每月录入）。以上为示例，不代表必须预置全部。

> 注意：“全勤奖”若设为每月录入，则不会根据考勤自动判定；需要人工录入实际金额。希望自动计算时，应单独确认计算规则。

### 4.5 员工薪资配置页面

- 展示当前员工已配置项目及生效日期。
- 点击「添加薪资项目」，从**全局项目库已启用项目**中选择。
- 每个员工同一有效配置中，同一个项目只能出现一次。
- 固定金额类项目：录入该员工对应的金额（元/月）。
- 每月录入类项目：仅配置“包含该项目”，具体金额留到每月薪资核算时填写。
- 系统自动计算类项目：只选择是否启用，不提供自由修改计算公式或单量提成率的输入框。
- 修改薪资配置时填写生效日期，并留存旧版本，保证已核算历史工资可追溯。

## 5. 数据字段

### 5.1 员工档案

| 字段 | 类型 | 必填 | 业务规则 |
|---|---|---|---|
| 员工ID | 系统唯一ID | 自动 | 不随转店、离职变化 |
| 姓名 | 字符串 | 是 | 去首尾空格后非空 |
| 手机号 | 字符串 | 是 | 基本格式校验；是否全局唯一待定 |
| 身份证号 | 字符串 | 是 | 格式校验；敏感信息安全存储与展示 |
| 所属门店ID | 门店关联 | 是 | 选择营业中门店 |
| 岗位 | 枚举 | 是 | 普通员工、副店长、店长 |
| 入职日期 | 日期 | 是 | 用于员工归属和后续计薪 |
| 离职日期 | 日期 | 离职时是 | 默认办理当天，可改为实际日期 |
| 员工状态 | 枚举 | 自动 | 在职、离职 |
| 创建/更新时间 | 日期时间 | 自动 | 内部记录 |

### 5.2 薪资项目库

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| 项目ID | 系统唯一ID | 自动 | 历史业务关联键 |
| 项目名称 | 字符串 | 是 | 建议不允许重复的启用项目名称 |
| 收支方向 | 枚举 | 是 | 加项或减项 |
| 计算类型 | 枚举 | 是 | 固定金额、每月录入、系统自动计算 |
| 系统预设 | 布尔 | 自动 | 预设计算逻辑不可随意修改 |
| 项目状态 | 枚举 | 自动 | 启用、停用 |
| 备注 | 字符串 | 否 | 用途说明 |

### 5.3 员工薪资配置

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 配置ID | 系统唯一ID | 自动 | 单条配置记录 |
| 员工ID | 员工关联 | 是 | 配置归属 |
| 项目ID | 薪资项目关联 | 是 | 从全局项目库选取 |
| 固定金额 | 金额（元） | 条件必填 | 固定金额项目填写；其他类型不填写 |
| 生效日期 | 日期 | 是 | 记录开始适用日期 |
| 失效日期/历史版本 | 日期/版本 | 自动 | 保留此前配置历史 |

金额使用两位小数；收支方向由项目决定，金额本身采用非负值以避免双重负号。

## 6. 业务规则

1. 员工归属单一门店；调店时更新当前归属，但应保留历史门店与生效日期。
2. 离职二次确认后员工从默认在职列表移除；历史考勤、排班和工资均保留。
3. 离职日期之后不允许创建该员工新的排班；历史周次应继续可见已发生的记录。
4. 员工岗位仅三类，不做岗位字典管理。
5. 全局项目库共享，员工只选择需要的项目，不强制套用按岗位统一模板。
6. 固定金额同一项目在不同员工间可以不同。
7. **单量提成：**配置了该项目的员工，按该员工适用门店的月总单量 × 0.1 元计提；未配置者不计提。月中转店的分摊规则尚未确认。
8. 自定义薪资项目仅支持固定金额或每月录入；自定义公式/复杂条件不在 V1.0 内。
9. 薪资项目被使用后不可物理删除；停用后不能新选用，既有历史配置及工资留存。
10. 薪资项目、员工配置更新不得覆盖已核算工资使用的数据快照。
11. 身份证号等敏感字段应按需展示并限制日志输出，避免无关页面泄露。
12. 请假、迟到、罚扣等金额必须有明确业务依据及合规规则；不允许仅因存在排班“假”状态就自动推算罚款。

## 7. 异常场景

| 场景 | 系统行为 |
|---|---|
| 未选门店新增员工 | 阻止保存并提示选择门店 |
| 姓名/手机号/身份证号/入职日期缺失 | 阻止保存并指出问题字段 |
| 身份证号格式不合法 | 阻止保存；具体校验以采用的证件类型为准 |
| 门店被停用 | 不可再分配新员工到该门店 |
| 员工办理离职时取消二次确认 | 员工资料及列表保持不变 |
| 已离职员工访问历史资料 | 可通过离职员工入口查找，不得物理丢失 |
| 同一薪资项目被重复添加 | 阻止添加并提示已存在 |
| 自定义项目选择“自动计算” | 不提供该选项，并说明 V1.0 不支持自定义公式 |
| 已使用的薪资项目被停用 | 既有历史数据保留，新增配置不能再选 |
| 薪资生效日期存在重叠或冲突 | 阻止产生同一员工同一项目的重叠有效记录 |
| 同月中途调店或调薪 | 保留有效日期信息；计薪分摊待薪资模块制定，不能擅自按整月某一家门店计算 |

## 8. 验收标准

- [ ] 门店下拉框切换后，正确展示对应门店的在职员工。
- [ ] 员工列表默认不显示离职员工。
- [ ] 可以新增员工，岗位仅有普通员工、副店长、店长。
- [ ] 可编辑员工基本信息、修改所属门店并保存历史归属。
- [ ] 点击离职必须二次确认；取消不生效，确认后从正常列表移除。
- [ ] 离职员工可以通过专门入口查看，历史数据不丢失。
- [ ] 可创建全局共享的自定义固定金额或每月录入薪资项目。
- [ ] 同一薪资项目可分配给不同员工，固定金额彼此独立。
- [ ] 同一员工可配置多个不同项目，但不能重复添加同一项目。
- [ ] 含单量提成项目的员工正确关联统一规则 0.1 元/单，界面无法修改系数。
- [ ] 员工不配置单量提成项目时不产生该项提成。
- [ ] 修改员工薪资配置保留历史版本，不改变既有已核算工资数据。

## 9. 待确认（留待考勤、绩效、薪资模块统一定义）

- 基本工资月中入职、离职或调薪时如何折算。
- 员工当月在多个门店工作的单量提成按何种方式分摊。
- 全勤奖是否只手动录入，还是要根据考勤自动判定。
- 店长绩效评估表字段、评分转换成工资的规则。
- 同一员工离职后重新入职，是激活历史员工还是创建新雇佣记录。
- 身份证号是否允许非中国大陆身份证（若允许需扩展证件类型）。
- 手机号是否全系统唯一。

> 这些问题影响后续计算规则，不改变员工模块已经确认的页面结构及可配置项目机制。
