# 餐饮员工管理系统 V1.0 — 门店管理 PRD

| 项目 | 内容 |
|---|---|
| 文档编号 | STORE-01 |
| 版本 | V1.0 |
| 状态 | 核心需求已确认 |
| 操作人 | 已登录的总部账号 |
| 前置依赖 | 总部登录 |
| 下游依赖 | 员工归属门店、按门店排班、单量导入及工资核算 |

## 1. 业务目标

统一维护直营门店的基础档案，提供员工归属、排班以及后续按门店归集单量和工资数据时使用的稳定门店 ID。

V1.0 只管理门店名称、地址、电话及状态，不增加区域、营业时间、经营负责人等复杂字段。

## 2. 功能范围

| 编号 | 功能 | 描述 |
|---|---|---|
| STORE-001 | 门店列表 | 展示已有门店及基本信息 |
| STORE-002 | 新增门店 | 新建门店档案 |
| STORE-003 | 编辑门店 | 修改名称、地址、电话 |
| STORE-004 | 停用门店 | 设为已停用，保留历史关联数据 |
| STORE-005 | 查看门店员工 | 从门店进入员工管理，并自动选中对应门店 |

**不做：**行政区域层级、加盟商/加盟门店管理、门店经营报表、营业时间、复杂组织机构、物理删除门店。

## 3. 页面结构及交互

### 3.1 门店列表页

- 主标题：门店管理。
- 列表列：门店名称、地址、联系电话、状态、操作。
- 操作：「编辑」「停用/启用（如开放重新启用）」「查看员工」。
- 页面入口：「新增门店」。
- 默认按创建时间或门店名称稳定排序（技术实现可选择其一）。
- 门店为空时展示空状态及「新增门店」。
- 停用门店仍可通过列表查看及查询历史数据；不能简单删除。

### 3.2 新增/编辑门店弹窗或页面

| 字段 | 控件 | 必填 | 校验与说明 |
|---|---|---|---|
| 门店名称 | 文本框 | 是 | 去除首尾空格后不得为空 |
| 门店地址 | 文本框 | 否 | 可为空 |
| 联系电话 | 文本框 | 否 | 可为空；填写时校验合理的电话号码格式 |
| 门店状态 | 系统值/展示 | 自动 | 新增默认“营业中”；通过独立状态操作停用 |

操作：「保存」「取消」。保存成功后在列表中可见。

## 4. 数据字段

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| 门店ID | 系统唯一ID | 自动 | 创建后不可修改，供各模块关联 |
| 门店名称 | 字符串 | 是 | 对用户展示；建议全系统禁止完全重复名称 |
| 门店地址 | 字符串 | 否 | 自由文本 |
| 联系电话 | 字符串 | 否 | 支持手机号/座机号，不作为唯一标识 |
| 门店状态 | 枚举 | 是 | 营业中、已停用 |
| 创建时间 | 日期时间 | 自动 | 系统记录 |
| 更新时间 | 日期时间 | 自动 | 系统记录 |

“门店ID”和时间字段为必要的内部字段，不要求全部显示在页面上。

## 5. 业务规则

1. **门店 ID 不变：** 改名或更换地址不会改变员工、排班、工资与单量的历史关联。
2. **新门店默认营业中：** 可以在员工模块被选为员工归属门店，在排班模块被选为排班门店。
3. **停用非删除：** 停用后保留门店档案及历史业务数据；不允许将该门店选为新员工归属门店或创建新的未来排班。
4. **已有员工处理：** 若门店仍有在职员工，停用前应显示明显提醒；是否阻止停用属于待确认项（见第 8 节），不能悄然删除/转移员工。
5. **历史记录可查：** 停用门店过往员工、排班、单量、工资仍应能按原门店 ID 查询。
6. **员工入口联动：** 「查看员工」跳到员工模块，自动选择该门店并默认只看该门店在职员工。
7. **电话与地址允许为空：** 空值不能阻止门店创建。

## 6. 异常场景

| 场景 | 预期行为 |
|---|---|
| 门店名称为空或只有空格 | 阻止保存并提示必填 |
| 门店名称与已有门店完全相同 | 提示重复，阻止创建（建议规则） |
| 电话格式明显不合法 | 提示修改或清空该选填字段 |
| 保存时网络异常 | 保留输入内容并显示失败，不重复创建 |
| 停用门店存在在职员工 | 显示在职人数与风险提示，按最终确认策略处理 |
| 从门店跳转员工列表但暂无员工 | 展示正确门店及空列表 |
| 访问停用门店历史数据 | 允许查看；禁止新增未来业务数据 |

## 7. 验收标准

- [ ] 可以创建仅填写门店名称的门店，默认状态为“营业中”。
- [ ] 可以修改门店名称、地址及联系电话，门店 ID 不变。
- [ ] 门店列表正确展示名称、地址、电话、状态。
- [ ] 门店名称为空时不能保存。
- [ ] 点击“查看员工”跳转员工模块，所选门店正确。
- [ ] 停用后门店历史档案与历史关联数据均保留。
- [ ] 停用门店不再允许创建新的未来排班、不能作为新员工所属门店。
- [ ] 保存失败时提供错误提示，不产生重复数据。

## 8. 待确认 / 实现前需定口径

- 若门店仍有在职员工，停用是**阻止并要求先转店/离职**，还是**允许停用但警示**？建议前者，以免出现无效归属。
- V1.0 是否提供“重新启用”按钮？建议提供，仍不做物理删除。
- 门店重名校验采用“完全同名”还是允许重名；推荐禁止完全同名。

> 除上述边界项外，门店信息范围、功能清单及简单列表交互均按已确认方案执行。
